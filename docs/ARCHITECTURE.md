# 技术架构与LLM接入

> 更新基准：2026-08-16

## 1. 总体分层

项目将确定性游戏规则与生成式演绎严格隔离：

- `app/original/original-entry.tsx`：轻量标题页；玩家选择后才动态载入完整运行时与数据库。
- `app/original/original-world.tsx`：浏览器主编排、正式状态、事件、战斗与环境LLM生命周期。
- `app/original/world-renderer.tsx`：素材延迟加载、事件视觉、静态地图缓存和Canvas绘制；不持有正式状态或发请求。
- `app/original/world-ui.tsx`：状态栏、战斗、小游戏、选择框、生活、主菜单和秘技等纯界面。
- `app/original/use-ambient-runtime.ts`：环境人口、暂停/复位、近身会话、请求世代、中止和玩家优先调度。
- `app/original/keybindings.ts`：按键映射与帮助文案的唯一数据源。
- `app/game-core/game-input.ts`：IME/编辑控件保护、禁止键、输入层优先级和命令解析。
- `app/game-core/fixed-step-clock.ts`：120Hz固定步进、最多12步补帧和后台暂停。
- `app/game-core/safe-storage.ts`：带失败原因的本地存储与JSON读写边界。
- `app/game-core/original-world.ts`：地图、转场、事件页和原作世界适配。
- `app/game-core/*-system.ts`：战斗、武功、装备、修炼、任务、生活、存档等确定性系统。
- `app/game-core/ambient-npc.ts`：NPC位置、随机活动、近身、朝向、临时会话和群聊轮次。
- `app/game-core/ambient-dialogue.ts`、`ambient-player.ts`：模型文本解析/清洗和主角环境会话的可复位状态。
- `app/game-core/npc-lore.ts`：人物身份、性格、说话方式、武境计算和统一角色事实档案。
- `app/game-core/lm-studio.ts`：流式聊天请求传输层。
- `app/game-core/save-system.ts`：版本化存档、旧档迁移、地图和坐标校验。
- `app/api/lm-studio/route.ts`：浏览器同源代理与本机LM Studio连接。

LLM只能产生展示文本，不能直接修改任务、物品、战斗、属性或存档。正式状态变化必须经过游戏核心系统验证和结算。

## 2. 环境模拟边界

- 只创建当前地图的NPC运行时。
- 只运行实际镜头框入的20×15格；地图边缘复用画布镜头的夹取矩形。
- 离开屏幕的NPC停止活动、清理临时会话并复位。
- 地图瓦片是可穿行的视觉画布；玩家与NPC忽略RMXP墙体、屋顶、家具及地形通行标记，仅保留地图边界与人物占位。
- 玩家与NPC、NPC与NPC统一使用Chebyshev距离1的3×3听觉圈。
- 可以先发现目标并走近，但只有近身后才能提交对话生成。
- 未近身的屏幕内NPC仍可生成自言自语和动作。

## 3. 会话模型

环境会话是临时session：

- 一对一对话按发起者、回应者顺序显示。
- 群聊不是广播，而是`甲 → 乙 → 丙`的定向接话链。
- 每人同一时刻只能面向一个接收者。
- 每轮发言前重新检查说话者与接收者的距离。
- 最近8条内容作为短期上下文；移动、散组、离屏、切图或打开模态界面即销毁。
- 对话内容只保留真正说出口的台词；背景、动作、神态和格式说明会被提示词与后处理过滤。
- 动作使用独立生成和清洗通道，正文完全来自LLM。
- 正式自由对话与环境会话共用不可改写人物事实：年龄、性别、门派、师承、外貌、武境阶梯与兵刃。提示词禁止模型根据姓名或服饰重猜性别，并禁止在台词中机械复述属性。
- 一对一和群组台词由 `ambient-bubble-layout.ts` 合并为有序共享会话卡；每条正文完整逐字测量、自动换行，不做两行裁切。
- 独白和环境动作保持独立气泡，并将共享会话卡作为布局障碍，避免互相遮挡。
- 主角参与的会话卡携带 `playerInvolved/playerName` 元数据，采用蓝色强调，锚定主角头顶向上增长，并在全部环境气泡之后绘制。
- 会话关系释放后仍在展示的定向尾句通过路由键继续归入原共享卡，避免拆成第二个独立气泡。

## 4. 统一环境LLM队列

环境生成只有一个调度入口，玩家可将总并发配置为1–3且永不超过3：

1. 玩家相关对话；
2. NPC近身对话；
3. NPC自言自语；
4. NPC动作。

纯NPC演绎最多占`总并发 - 1`个通道，始终为玩家保留1个通道。同优先级按入队时间排序。生成尚未取得资源时不显示占位文本，也不推进发言轮次。

自由对话、战斗和其他正式模态打开时会暂停环境模拟，因此不会与背景NPC争抢本地模型。请求均绑定会话世代和中止控制器，过期响应无法写回新地图或新会话；离开游玩界面或卸载世界时，自由对话与战报请求也会统一中止。同名地图事件使用精确`eventId`记录接收者，名字索引仅作会话内近身回退，避免定位到远处同名NPC。

## 5. LM Studio默认接入

浏览器请求同源端点：

```text
POST /api/lm-studio
```

代理默认连接：

```text
POST http://127.0.0.1:1234/api/v1/chat
```

请求使用LM Studio的OpenAI兼容流式接口。模型不可用、超时或输出无法清洗时，本轮演绎静默取消；代码中没有默认台词或默认动作兜底。
标题页提供服务地址、模型名、超时和并发设置。打开设置不会探测服务；只有玩家点击检测按钮才通过受控端点发起健康检查。设置保存在独立浏览器键中，不进入游戏存档。传输层统一施加10条/12,000字符上下文、512 tokens上限、SSE增量解析和可取消超时。

## 6. 可选的外部传输扩展

默认产品只支持LM Studio。如维护者明确选择接入外部API，应保留游戏侧接口并在服务端适配传输：

1. 在服务端新增Provider适配器，将统一消息转换为目标API格式。
2. 保留`AbortSignal`，确保移动和切图能够真正取消请求。
3. 将API密钥放在未提交的环境变量中。
4. 保持输出token限制、超时、并发上限和玩家优先级。
5. 云模型响应仍必须经过现有台词/动作清洗与会话世代校验。
6. 不允许Provider返回的工具调用直接修改游戏状态；未来如加入工具调用，必须经过白名单命令和确定性验证器。

## 7. 存储与SSR边界

标题首屏以确定性的`fresh()`渲染，挂载后才在零延时任务中经`readJsonStorage()`和`parseSave()`恢复本地存档。写入经`writeJsonStorage()`区分存储禁用、配额不足和序列化失败；损坏JSON或格式错误只提示，不自动删除原值。模型设置使用同一安全边界，但与游戏存档完全分离。

## 8. 测试与质量门槛

`npm run check`依次执行类型检查、ESLint、核心可执行源码覆盖率、生产构建、体积/资源预算、服务端HTML渲染测试和Chromium E2E。覆盖率不计测试文件、静态数据库与由浏览器/视觉回归单独守门的Canvas绘制层，避免用测试代码本身虚高总数。CI 将高危依赖审计、静态检查、覆盖率与构建拆成并行任务；PR 跑Chromium，`main`推送后并行跑Chromium、Firefox和WebKit。E2E覆盖标题按需加载、零模型请求、说明页、显式模型检测、安全存档导入与基础axe无障碍扫描。

## 9. 首屏、绘制与资源预算

- 根路由与`/original`共用轻量标题壳；完整世界、存档解析和原始数据库按操作动态载入。
- `maps.json`、人物/武功数据及物品数据各自形成独立分块；任何客户端JavaScript分块不得超过500,000字节，标题静态依赖图gzip总量不得超过125KiB，且不得包含完整世界、LM或存档核心。
- 地形、建筑与固定装饰缓存到静态地图画布；动画循环上限30 FPS，页面隐藏时暂停，动态人物通过索引查找。
- 玩家图集优先载入，NPC图集按首次使用载入；位图使用高质量WebP，总`game-assets`预算为10 MiB。预算脚本同时校验manifest缺失文件、重复登记与孤儿资源。
- `npm run budgets`在构建后执行并阻止体积回退。

NPC数值由 `scripts/rebalance-npcs.mjs` 按战斗等级在原始数据中直接重新分配，不再有运行时倍率强化层：战斗等级只算「专门武功」(id≥12)——原版给商人/平民填了很高的基本武功作为数据伪影，不计入，因此卖花妞等非战斗人物保持低血；按原始档位分为宗师/顶尖高手/高手三档，档内全部战斗武功统一高位、数值按档位取天花板比例，其余 NPC 按曲线平滑下降；血/内力天花板取适中值（12000/45000，玩家可通过物品无上限堆内力到 65535/血~16783，故顶级宗师与高属性玩家旗鼓相当但战斗偏长），NPC经验分档对标玩家（45%-80%）避免命中被经验碾压，NPC 加力(`fp_plus`)按等级/3参与战斗伤害；伤害公式的 force 倍率在 `combat.ts` 封顶×2.0，防止高 force 武功放大成秒人伤害（force 型武功与 damage 型武功本身的强弱差异仍保留，因此同为宗师也有难易之别）；内置修改器上限对齐规则可达值：内力/法力 65535、气血 ~16783（一键宗师给满级经验、加力/法点提到内功/法术有效等级一半）。动态任务敌人保持玩家相对缩放；玩家经验统一封顶1000万；法术对超过5000的气血、内力与法力使用平方根递减输入，持续燃烧只取法力压制差的5%至8%，不使用目标气血百分比硬上限。`npc-combat-scaling.ts` 仅保留 `npcCombatLevel` 供敌方绝招触发概率使用。
