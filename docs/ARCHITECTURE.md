# 技术架构与LLM接入

> 更新基准：2026-08-08

## 1. 总体分层

项目将确定性游戏规则与生成式演绎严格隔离：

- `app/original/original-world.tsx`：浏览器主运行时、界面、画布绘制、输入、模态窗口和环境LLM调度。
- `app/game-core/original-world.ts`：地图、转场、事件页和原作世界适配。
- `app/game-core/*-system.ts`：战斗、武功、装备、修炼、任务、生活、存档等确定性系统。
- `app/game-core/ambient-npc.ts`：NPC位置、随机活动、近身、朝向、临时会话和群聊轮次。
- `app/game-core/npc-lore.ts`：人物身份、性格、说话方式、武境计算和统一角色事实档案。
- `app/game-core/lm-studio.ts`：流式聊天请求传输层。
- `app/api/lm-studio/route.ts`：浏览器同源代理与本机LM Studio连接。

LLM只能产生展示文本，不能直接修改任务、物品、战斗、属性或存档。正式状态变化必须经过游戏核心系统验证和结算。

## 2. 环境模拟边界

- 只创建当前地图的NPC运行时。
- 只运行实际镜头框入的20×15格；地图边缘复用画布镜头的夹取矩形。
- 离开屏幕的NPC停止活动、清理临时会话并复位。
- 地图瓦片是可穿行的视觉画布；玩家与NPC忽略RMXP墙体、屋顶、家具及地形通行标记，仅保留地图边界与人物占位。
- 玩家与NPC、NPC与NPC统一使用Chebyshev距离1的3×3听觉圈。
- 可以先发现目标并走近，但只有近身后才能提交对话生成。
- 未近身的屏幕内NPC仍可生成自言自语和动作。

## 3. 会话模型

环境会话是临时session：

- 一对一对话按发起者、回应者顺序显示。
- 群聊不是广播，而是`甲 → 乙 → 丙`的定向接话链。
- 每人同一时刻只能面向一个接收者。
- 每轮发言前重新检查说话者与接收者的距离。
- 最近6条内容作为短期上下文；移动、散组、离屏、切图或打开模态界面即销毁。
- 对话内容只保留真正说出口的台词；背景、动作、神态和格式说明会被提示词与后处理过滤。
- 动作使用独立生成和清洗通道，正文完全来自LLM。
- 正式自由对话与环境会话共用不可改写人物事实：年龄、性别、门派、师承、外貌、武境阶梯与兵刃。提示词禁止模型根据姓名或服饰重猜性别，并禁止在台词中机械复述属性。

## 4. 统一环境LLM队列

环境生成只有一个调度入口，最大同时运行3个请求：

1. 玩家相关对话；
2. NPC近身对话；
3. NPC自言自语；
4. NPC动作。

纯NPC演绎最多占2个通道，始终为玩家保留1个通道。同优先级按入队时间排序。生成尚未取得资源时不显示占位文本，也不推进发言轮次。

自由对话、战斗和其他正式模态打开时会暂停环境模拟，因此不会与背景NPC争抢本地模型。请求均绑定会话世代和中止控制器，过期响应无法写回新地图或新会话。

## 5. LM Studio默认接入

浏览器请求同源端点：

```text
POST /api/lm-studio
```

代理默认连接：

```text
POST http://127.0.0.1:1234/v1/chat/completions
```

请求格式兼容OpenAI Chat Completions。模型不可用、超时或输出无法清洗时，本轮演绎静默取消；代码中没有默认台词或默认动作兜底。

## 6. 替换其他LLM API

建议保留游戏侧接口和更换Provider实现：

1. 在服务端新增Provider适配器，将统一消息转换为目标API格式。
2. 保留`AbortSignal`，确保移动和切图能够真正取消请求。
3. 将API密钥放在未提交的环境变量中。
4. 保持输出token限制、超时、并发上限和玩家优先级。
5. 云模型响应仍必须经过现有台词/动作清洗与会话世代校验。
6. 不允许Provider返回的工具调用直接修改游戏状态；未来如加入工具调用，必须经过白名单命令和确定性验证器。

## 7. 测试与质量门槛

`npm test`依次执行生产构建、TypeScript逻辑/视觉测试和服务端HTML渲染测试。当前共169项测试，覆盖地图事件、全图穿行与边界、战斗伤害/法术/燃烧公式、NPC数值重平衡、修改器上限、装备、武功、任务目标过滤、门派限制、特殊人物事件、存档、NPC活动窗口、听觉距离、对话顺序、角色事实约束、队列优先级、提示词约束、气泡图层和SSR入口。

NPC数值由 `scripts/rebalance-npcs.mjs` 按战斗等级在原始数据中直接重新分配，不再有运行时倍率强化层：按原始档位分为宗师/顶尖高手/高手三档，档内全部战斗武功统一高位、数值按档位取天花板比例，其余 NPC 按曲线平滑下降；血/内力天花板贴近满级玩家（3650/13000，玩家仍最强），NPC经验分档对标玩家（45%-80%）避免命中被经验碾压，NPC 加力(`fp_plus`)按等级/3参与战斗伤害；伤害公式的 force 倍率在 `combat.ts` 封顶×2.0，防止高 force 武功放大成秒人伤害（force 型武功与 damage 型武功本身的强弱差异仍保留，因此同为宗师也有难易之别）；内置修改器上限对齐 `fullHp`/`fullFp`/`fullMp` 真实容量。动态任务敌人保持玩家相对缩放；玩家经验统一封顶1000万；法术对超过5000的气血、内力与法力使用平方根递减输入，持续燃烧只取法力压制差的5%至8%，不使用目标气血百分比硬上限。`npc-combat-scaling.ts` 仅保留 `npcCombatLevel` 供敌方绝招触发概率使用。
